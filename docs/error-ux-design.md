# AnswerDesk AI エラーUX設計

## 1. 目的
ユーザーおよび管理者がエラー発生時に迷わないよう、主要な失敗ケースと画面上の見せ方を定義する。

---

## 2. 基本方針
- 技術的すぎる文言は避ける
- 次に取る行動が分かる文言にする
- 管理者画面では必要に応じて詳細も見せる
- 公開画面では内部情報を見せない

---

## 3. ケース別UX

### 3.1 slug重複
対象: ボット設定画面

表示:
- 「このURLはすでに使用されています。別のslugを入力してください。」

補助:
- 入力欄直下に表示
- 保存ボタンは無効化

### 3.2 非公開ボットアクセス
対象: 公開チャット画面

表示:
- 「このチャットは現在公開されていません。」
- トップへ戻るリンク

### 3.3 存在しないslug
対象: 公開チャット画面

表示:
- 「ページが見つかりませんでした。」
- トップへ戻るリンク

### 3.4 PDFアップロード失敗
対象: 文書アップロード画面 / 文書一覧画面

表示:
- 「PDFの取り込みに失敗しました。ファイル形式や内容を確認して再度お試しください。」
- 詳細エラーは管理画面で確認可能

### 3.5 テストチャット失敗
対象: テストチャット画面

表示:
- 「現在回答を生成できませんでした。時間をおいて再度お試しください。」

### 3.6 公開チャット未ヒット
対象: 公開チャット画面

表示:
- ボット設定の fallback_message
- 問い合わせURL / メール導線

### 3.7 認証切れ
対象: 管理画面全体

表示:
- 「ログインの有効期限が切れました。再度ログインしてください。」

動作:
- ログイン画面へ遷移

---

## 4. 文言設計方針
- 短い
- 原因をぼかしすぎない
- ただし内部スタックトレース等は出さない
