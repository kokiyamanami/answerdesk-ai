## 1. 生成AIの回答エラー対応

### 調査結果
**現時点では再現しませんでした。** 本番 API に FAQ 付きボットを作って質問したところ、
正常に回答（引用付き・4.8秒）が返っています。App Runner ログにも直近のエラーはなし。

エラーが出ていたのは、この日の少し前まで **App Runner が OpenAI API に到達できず
チャットが約90秒ハングしていた**問題（VPCコネクタ + NAT無し。`docs/aws-redeploy-runbook.md` §9 で対応済み）
だったと考えられます。

### 追加で入れた対策（`backend/app/services/rag_service.py`）
OpenAI 側の一時的な不調で 500 エラー（フロントに「エラーが発生しました」）を出さず、
フォールバックメッセージに落とすようにした:

- embedding 生成失敗 → fallback
- 回答可否判定（LLM）失敗 → 判定をスキップして回答生成へ進む
- 回答生成失敗 / 空レスポンス → fallback
- `message.content` が `None` のケースをガード

- [ ] デプロイ後、実際のボット（`teppenenglish` など）で回答が返るか
- [ ] もし特定のボット・質問でまだエラーが出るなら、その質問文を教えてください（ログを追います）

## 2. FAQ の CSV インポート / エクスポート

### 実装
**バックエンド** `backend/app/api/routers/faq.py`:
- `GET /api/faqs/export` — CSV ダウンロード。列 `question,answer,category,sort_order`。Excel 対応で UTF-8 BOM 付き
- `POST /api/faqs/import` — CSV アップロード（multipart）。`{created, skipped, errors}` を返す

**フロント** `frontend/src/pages/FAQPage.tsx`:
- 「⬆ CSVインポート」「⬇ CSVエクスポート」ボタンを追加
- インポート結果（追加n件 / スキップn件 / エラー）をアラート表示

### 仕様上の判断（必要なら変更します）
| 項目 | 現在の挙動 | 備考 |
|---|---|---|
| インポート方式 | **追記**（既存FAQは消さない） | 「洗い替え」にすることも可 |
| 必須列 | `question`, `answer` | どちらか空の行はスキップ |
| 任意列 | `category`, `sort_order` | `sort_order` が数値でなければ 0 |
| 文字コード | UTF-8 / Shift_JIS 自動判定 | |
| サイズ上限 | 2MB | |
| 埋め込み生成 | 1行ずつ同期実行（1行 commit） | 大量行だと時間がかかる。100行で1〜2分想定 |
| 重複 | チェックなし（同じ質問でも追加される） | 重複スキップを入れるべきか要判断 |

### 確認してほしいこと
- [ ] インポートは「追記」でよいか、「全置き換え」にするか
- [ ] 重複（同一 question）をスキップする挙動を入れるか

## 3. 精度テスト機能

### 実装
公開前に想定質問を登録 → 一括実行 → 回答/フォールバック有無/retrievalスコアを一覧確認できる機能。

**バックエンド**:
- 新テーブル `bot_test_questions`（migration `0009_create_bot_test_questions.py`）
  - `question`, `note`, および直近実行結果 `last_answer` / `last_fallback` / `last_score` / `last_run_at`
- 新モデル `backend/app/models/bot_test_question.py`
- 新ルーター `backend/app/api/routers/test_question.py`（`/api/test-questions`）
  - `GET ""` 一覧 / `POST ""` 追加 / `PATCH /{id}` / `DELETE /{id}`
  - `POST /run` — 全質問を RAG パイプライン（`answer_question`）に通す。**会話ログには保存しない**。結果を各行に保存して返す

**フロント**:
- 新ページ `frontend/src/pages/AccuracyTestPage.tsx`
- ルート `/app/accuracy`、サイドバーに「🧪 精度テスト」を追加

### 仕様上の判断（必要なら拡張します）
| 項目 | 現在 | 拡張案 |
|---|---|---|
| 期待値との照合 | なし（回答テキストとフォールバック有無を目視確認） | 「期待キーワードを含むか」で自動 PASS/FAIL 判定を追加可能 |
| 実行履歴 | 直近1回のみ各行に上書き保存 | 実行ごとの履歴テーブルを持たせて推移を見られるようにする案 |
| 実行方式 | 同期（質問数ぶん OpenAI 呼び出しを直列）。20問で1〜3分 | 非同期ジョブ化 |
| 公開ブロック連携 | なし | 「フォールバック率が高いと公開時に警告」等 |

### 確認してほしいこと
- [ ] 「期待キーワード」による自動 PASS/FAIL 判定は必要か（あると公開判断が楽）
- [ ] 実行履歴（推移）を残す必要があるか
